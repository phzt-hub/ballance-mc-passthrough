# 自由视角：现成 mod 调研

来源：<https://dl.ballance.top/resource/877>（Ballance 社区资源站，2026-11-01 上传）

## 一、这个 mod 是什么

| 项 | 值 |
|---|---|
| 名称 | `FreeFirstPersonCamera` |
| 作者 | @Entity_303-E3 |
| 类型 | mod（BRP 包，44,371 B，内含 `bmod` 44,544 B + `bmodp` 41,984 B） |
| 运行环境 | **BML+ 0.3.4+ / BML 0.3.40+** |
| 功能 | 第一人称 + 鼠标自由转视角；`F` 键切换第一/第三人称 |

## 二、它对我们的价值（不是"能直接装"，是"有答案了"）

**不能直接用在 Ballanced 上**：它是 `bmod`，加载器是 BML，挂在**原版 `Player.exe`** 上；
而我们选的主线是 `Ballanced`（SDL3 运行时），是另一套插件体系。

但它把三件我不确定的事变成了已知：

1. **相机是可以被外部接管的**，而且接管后关卡脚本不炸（还能 F 键切回第三人称）。
   → 我们担心的"难度脚本抢相机控制权"在原版上已有现成解法，可以照着找 Ballanced 里同一层。
2. **自由视角必然改玩法**，社区给出的答案是**默认不改**：

   | | `360Mode = 1` | `360Mode = 0`（默认） |
   |---|---|---|
   | 俯仰范围 | 无限 | **±85°** |
   | 左右转轴 | 视野自身的 up 轴 | **世界 Y 轴** |
   | 施力方向 | 完整跟随视线 | **水平（与原版一致）** |

   → 我们做自由视角时**直接沿用 `360Mode = 0` 的默认值**，别自己发明。
3. **有 MIT 参考实现**：致谢里的 `Xenapte/MyBMLMods/FreeViewRotation`（MIT，`main.cpp` 仅 **187 行**），
   核心是 `m_bml->GetInputManager()->GetMouseRelativePosition()` 拿鼠标位移 → 转角度。
   另一个 `FirstPersonCamera` 作者标注"未找到源码"。

## 三、由此产生的两条战略分叉

Ballance 的 mod 生态是 **BML / `bmod`**，`Ballanced` 是另一套运行时。两者不通用。

| 路线 | 好处 | 代价 |
|---|---|---|
| **Ballanced（当前主线）** | 源码在手：深度、相机、碰撞全可直接改；Linux 可开发 | 放弃整个 bmod 生态；自由视角要自己写（≈187 行参考 + 接管相机） |
| **原版 Player.exe + BML** | 自由视角**直接装**；将来地图/统计类 mod 全能用 | 32 位 D3D9 注入；深度要走 `IDirect3D9` 面下载；只有 Windows |

**待核（决定 A 路线值不值）**：BML+ 是否公开渲染钩子（`IBML` 上有没有 EndScene / RenderManager 级别的回调）。
若有，A 路线取深度只比自己写多点工作量，却能白拿整个 bmod 生态。

## 四、按键冲突

`F` 在我们这里已经被 Minecraft 占用（交换副手）。自由视角切换键需要重映射，
或用"仅在第一人称时转发 F 给 MC"这类条件规则。
